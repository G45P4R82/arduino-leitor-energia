# Experimento iot004 - Ethernet e OTA

## Objetivo

Validar uma placa ESP32/Wemos com shield Ethernet W5100 e criar um fluxo de atualizacao OTA usando GitHub Actions e GitHub Releases.

## Hardware testado

- ESP32 Wemos D1 R32
- Shield Ethernet W5100
- Arduino Mega 2560
- Sensor SCT-013

## Teste ESP32 + W5100

Firmware de diagnostico configurado com:

- SPI: SCK GPIO18, MISO GPIO19, MOSI GPIO23;
- CS: GPIO5;
- Sensor no GPIO36/ADC1;
- DHCP;
- Teste HTTPS via `SSLClient`;
- Trust anchors do GitHub.

Resultado:

```text
Hardware Ethernet: nao detectado
Link Ethernet: down
Falha no DHCP
```

O ESP32 foi detectado corretamente pela USB, leu o sensor, mas nao conseguiu conversar com o W5100 pelo SPI. Os LEDs do shield piscando confirmam apenas alimentacao/link fisico, nao comunicacao SPI.

Hipoteses:

- W5100 trabalha com logica de 5 V e ESP32 trabalha com 3,3 V;
- Falta de conversor de nivel logico;
- Shield W5100 pode nao ser eletricamente compativel com o ESP32;
- CS, SPI ou alimentacao podem estar incorretos.

## Teste Mega + W5100

O Arduino Mega foi testado com o mesmo shield.

Resultado:

```text
DHCP: OK
IP: 192.168.15.19
Sensor: leitura de corrente funcionando
```

O Mega e eletricamente compativel com o W5100 e resolve a comunicacao basica Ethernet.

## Teste TLS no Mega

Foi instalada e testada a biblioteca `SSLClient` sobre `EthernetClient`.

A compilacao falhou inicialmente por falta de `std::vector` no ambiente AVR. Um shim experimental permitiu chegar ao calculo de memoria, mas o resultado foi:

```text
Flash utilizada: 168594 bytes
SRAM utilizada: 26981 bytes
SRAM disponivel no Mega: 8192 bytes
```

Resultado: TLS seguro nao cabe no Mega. A SRAM necessaria ultrapassa em muito a capacidade da placa.

## Teste HTTP sem TLS

Foi verificado que os enderecos HTTP do GitHub redirecionam para HTTPS:

```text
HTTP 301 -> HTTPS
```

Portanto, remover o TLS nao resolve o acesso direto ao GitHub. Mesmo que um servidor HTTP local fosse usado, o Mega ainda nao possui um bootloader OTA para gravar uma nova aplicacao com seguranca.

## Conclusao

```text
Mega + W5100 + Ethernet: funciona
Mega + W5100 + TLS: inviavel por memoria
Mega + W5100 + OTA seguro: nao funciona com bootloader padrao
ESP32 + W5100 direto: problema de niveis logicos/SPI
```

O bypass do TLS remove a criptografia, mas nao resolve a ausencia de mecanismo de gravacao OTA no Mega.

## Alternativas

### ESP32 + W5500

Alternativa recomendada. O W5500 deve ser compativel com logica de 3,3 V e o ESP32 possui memoria, particoes OTA e recursos para TLS.

### ESP32 + W5100 com conversor

Pode funcionar se todas as linhas SPI forem adaptadas de 5 V para 3,3 V e o mapeamento de CS/SPI estiver correto.

### ESP32 como gateway

O ESP32 baixa o firmware via HTTPS e grava o Mega pela serial ou ICSP. Exige conexao fisica entre as placas e adaptacao de nivel.

### Mega com OTA HTTP customizado

Possivel apenas com bootloader customizado, protocolo proprio e risco de inutilizar a placa em caso de interrupcao. Nao recomendado para producao.
